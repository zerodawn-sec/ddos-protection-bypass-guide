# CDN源站IP发现技术：绕过CDN防护找到真实服务器

## 概述

CDN（内容分发网络）是Web服务最常见的DDoS防护层。当目标站点部署了CDN，直接压力测试只能打到CDN边缘节点，无法触及源站。要真正测试源站的抗压能力，首先需要发现源站真实IP地址。本文从技术分析角度，拆解主流的CDN源站发现方法。

## CDN防护原理

CDN的工作机制：

- 用户请求 → DNS解析到CDN边缘节点 → CDN回源获取内容 → 返回用户
- 源站真实IP不直接暴露给用户
- 所有流量经CDN节点中转，DDoS压力被CDN吸收

CDN防护的弱点：**一旦源站IP暴露，攻击者可以直接绕过CDN打源站**。

## 源站IP发现方法

### 1. DNS历史记录

最基础也最有效的方法。CDN接入前，域名直接解析到源站IP。这些历史DNS记录被各种服务存档：

- SecurityTrails、DNSDB、ViewDNS等平台提供历史DNS查询
- 查找域名在接入CDN之前的A记录
- 准确率：高（前提是域名曾直连源站）

**防御建议**：接入CDN后更换源站IP，或在源站只允许CDN节点回源。

### 2. 子域名扫描

主域名接入了CDN，但子域名可能没有：

- 内部管理面板、API端点、邮件服务器等子域名
- 这些子域名可能直接解析到源站IP
- 工具：Subfinder、Amass、DNS暴力枚举

典型发现路径：
- `api.example.com` → 直连源站
- `mail.example.com` → 邮件服务器（常与Web同主机）
- `dev.example.com` / `staging.example.com` → 测试环境未配CDN

### 3. SSL证书指纹

CDN节点和源站可能使用不同SSL证书。通过证书透明度日志（CT Log）查询：

- 在crt.sh查询域名的历史证书
- 证书中可能包含源站IP或内部主机名
- 不同子域名的证书签发IP可能指向同一源站

### 4. 邮件头分析

如果目标服务器发送过邮件（如密码重置邮件），邮件头中包含源站信息：

- `Received`头部显示邮件发送服务器的IP
- 邮件服务器常与Web服务器同主机或同网段
- 注册账户触发邮件 → 分析邮件头 → 获取源站IP

### 5. 全网扫描

最暴力但有效的方法：

- 使用Shodan/Censys扫描全网IPv4
- 匹配目标域名特征（HTML标题、favicon哈希、HTTP响应头）
- 找到返回相同页面内容的IP

Censys/Shodan搜索技巧：
- 按favicon hash搜索
- 按特定HTML内容搜索
- 按SSL证书字段搜索

### 6. 回源协议探测

某些CDN配置存在信息泄露：

- 错误页面泄露源站信息（如Nginx默认错误页）
- CORS配置暴露回源域名
- HTTP响应头泄露内部IP（X-Forwarded-For等配置错误）

## 发现源站后的测试方向

找到源站IP后，压力测试才有意义：

1. **直接L4测试**：SYN/UDP直接打源站IP，绕过CDN防护
2. **L7测试**：Host头指向源站IP的HTTP请求，验证源站应用层抗压
3. **防护验证**：测试源站是否有独立的L4/L7防护（非CDN提供的）

## 防御对策

了解源站发现方法有助于加固防护：

- 源站防火墙只允许CDN节点IP回源（白名单策略）
- 接入CDN后更换源站IP
- 所有子域名统一接入CDN
- 邮件服务使用独立IP/服务器
- 关闭错误页面信息泄露
- 配置WAF规则拦截非CDN来源请求

## 总结

CDN防护的核心安全前提是源站IP保密。一旦通过DNS历史、子域名、证书指纹、邮件头或全网扫描发现源站IP，CDN防护将被直接绕过。压力测试需要模拟这种绕过场景，验证源站是否有独立防护能力。
