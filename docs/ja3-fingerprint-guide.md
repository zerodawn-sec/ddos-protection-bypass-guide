# TLS指纹与验证机制技术解析

## 为什么TLS握手会"泄密"

TLS ClientHello消息携带密码套件列表、扩展字段、椭圆曲线参数等信息，其排列组合构成客户端的"指纹"。同一浏览器版本的指纹高度稳定，而脚本库（curl、Python requests）的指纹与真实浏览器差异巨大——这是防护系统识别非人类流量的核心依据之一。

## JA3与JA4

- **JA3**：对ClientHello中的版本、密码套件、扩展做MD哈希，输出32位指纹。2017年提出后成为行业标准。
- **JA4**：2023年提出的升级格式，不再哈希而是分段可读（如 `t13d1516h2_8daaf6152771_b186095e22b6`），前段记录协议/域名/ALPN特征，中段是套件摘要，后段是扩展摘要。可读性更好，且支持局部匹配。

两者的共同价值：**不以User-Agent为准，而以密码学特征为准**。UA可以随意伪造，ClientHello的构造却依赖底层TLS库实现。

## 常见指纹对比

| 客户端类型 | 特征 | 防护判定 |
|-----------|------|---------|
| Chrome最新版 | 扩展排序标准，带ECH/GREASE | 信任 |
| Python requests | 套件少、无GREASE、扩展固定序 | 高危 |
| curl | 类似requests，指纹库公开 | 高危 |
| 定制Go客户端 | 取决于TLS配置，常见配置已被收录 | 中危 |
| 指纹伪造客户端 | 模仿浏览器套件序列 | 需行为层二次判定 |

## 人机验证机制

### JS Challenge（5秒盾）

返回一段必须执行的JavaScript，计算结果携带在后续请求中。无JS引擎的客户端直接卡死在第一关。

### Turnstile

Cloudflare的验证组件，在后台综合浏览器环境信号（画布渲染、字体、时序）判定，多数情况无需人工点击。

### 行为指纹

鼠标轨迹、滚动惯性、按键间隔——模拟器最难伪造的维度。

## 对安全测试的意义

评估CDN防护强度时，需要能模拟真实浏览器TLS指纹的测试方法，否则流量在第一层握手就被拦截，测不出后续层的真实承载。支持指纹模拟的云端方法库可参考 [zerodawnsec.com 方法列表](https://zerodawnsec.com/all-methods.html)，TLS专项与CLOUD类方法均具备完整握手模拟能力。
