# 反爬虫验证体系拆解：三层防护的通过逻辑

现代WAF的反bot体系不是单点，是三层叠加：JS质询、TLS指纹、行为分析。只突破一层没用，三层都要对得上。

## 第一层：JS质询（5秒盾）

浏览器执行一段JS，算出结果回传，服务端验证后放行并发cookie。

识别逻辑：
- 无JS引擎的客户端直接死在这层
- JS执行结果有时效（通常30分钟-数小时）
- 质询失败会升级：静态页 → 交互式验证码

应对思路：真实浏览器内核（有头/无头+补环境）是唯一稳定路径，纯协议模拟在这层成本极高。

## 第二层：TLS指纹（JA3/JA4）

握手阶段的ClientHello被哈希成指纹，与已知工具特征比对。

识别逻辑：
- curl/python-requests的指纹在黑名单里
- 指纹库持续更新，昨天能过的今天可能就失效
- CDN层（Cloudflare等）默认开启基础指纹检查

应对思路：自定义TLS栈（修改cipher suite顺序、扩展字段顺序）让指纹脱离工具特征区。

## 第三层：行为验证

IP信誉、请求频率、鼠标轨迹、会话一致性。

识别逻辑：
- 同一IP短时间大量不同会话 → 标记
- 请求间隔过于均匀（机器特征）→ 标记
- 无次要资源请求（只拉HTML不拉CSS/JS/图片）→ 标记

应对思路：住宅IP池+人类化节奏（随机延迟、完整资源加载、会话复用）。

## 三层的耦合关系

关键认知：**三层是AND关系**。JS质询过了但TLS指纹是curl的，照样拦。这就是为什么"过了5秒盾"和"能稳定访问"是两个难度量级。

实际测试中建议分层验证：先单独测每层的通过率，再测组合通过率。组合通过率低于任何单层，差距就是耦合损耗。
